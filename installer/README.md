# XREAL Russian Updater v0.6.0-test

Переносимое приложение Windows 10/11 x64. EXE и BIN скачиваются отдельно.
Приложение принимает выбранный BIN после проверки формата, CRC контейнера,
всех внутренних SHA256 и модели. Привязки к одному фиксированному SHA256 нет.
[Инструкция установки](../README.md) · [Тест Real3D и AI HDR для обычного One](ONE-TEST.md).

Pilot 1.9.1 предназначен для One (USB PID `0438`) и One Pro (USB PID `0436`, SKU `X1112010`/`X1112011`); официальный Pilot для обеих моделей совпадает по MD5. Прежний экспериментальный Pilot 2.0 допускает только One Pro `X1112010`. Новый One-only BIN имеет внутреннюю метку `pilot/xreal-target.json`, включённую в checksums.sha256, и допускается только на PID `0438`. На One проверка ещё не выполнена. Приложение принимает поддерживаемые исходные версии при точном совпадении SoC; после записи проверяет выбранную версию. [Обоснование второго SKU One Pro](compatibility.md).

## Использование

1. Запустите EXE и подключите очки. Закройте другие обновляторы.
2. Нажмите «Обновить список», выберите устройство, затем «Выбрать BIN…» и скачанный BIN.
3. Нажмите «3. Установить выбранную прошивку» и дождитесь сообщения «Готово. Файлы проверены».
4. Для уже установленного варианта используйте «Проверить без записи».

Интерфейс поддерживает масштаб Windows, изменение размеров окна и прокрутку. Установка не начинается автоматически при запуске или выборе устройства.

## Как работает

Проверяются целостность выбранного BIN и совместимость с моделью/версиями. Используется HID-протокол веб-обновлятора: 4628 — заголовок, 4629 — последовательные блоки до 490 байт, 4630 — применение. Проверяются CRC, команда и статус ответа. Дополнение HID-отчёта Windows учитывается.

После принятия пакета приложение ждёт перезапуска и сравнивает пять файлов обычного варианта, девять файлов эксперимента One Pro или одиннадцать файлов эксперимента One. При разрыве соединения повторяется только чтение целиком с новым соединением, до трёх попыток. Отдельные блоки записи автоматически не повторяются. Обновлятор не переключается на другое устройство. Полный резервный образ не создаётся.

Диагностика ошибок: `%LOCALAPPDATA%/XREAL-Russian-Updater/last-error.txt`. EXE не подписан сертификатом издателя.

## Сборка

Тестовый выпуск для обычного One: `powershell -ExecutionPolicy Bypass -File installer/build-one-test.ps1`.
Нужны локальные исходные пакеты, перечисленные в [ONE-TEST.md](ONE-TEST.md).
Результат — два отдельных файла в `outputs/xreal-one-real3d-hdr-test/`.

На Windows x64 с Python 3.13 из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File installer/build.ps1
```

Скрипт создаёт окружение в `work/installer-venv`, устанавливает зависимости, выполняет тесты, собирает EXE и ZIP в `outputs/xreal-windows-installer/`. Два BIN копируются из `outputs/xreal-russian-firmware/` и `outputs/xreal-pilot2-real3d-cpu/`. Упаковка EXE — PyInstaller one-file; BIN в него не встраиваются.

## Диагностика сборки

```text
XREAL-Russian-Updater-v0.6.0-test.exe --self-test report.json --bin XREAL-One-Pilot2-RU-Real3D-AIHDR-TEST.bin
XREAL-Russian-Updater-v0.6.0-test.exe --check-device report.json --bin XREAL-One-Pilot2-RU-Real3D-AIHDR-TEST.bin
XREAL-Russian-Updater-v0.6.0-test.exe --verify-device report.json --bin XREAL-One-Pilot2-RU-Real3D-AIHDR-TEST.bin
```

Первый режим проверяет выбранный BIN и загрузку интерфейса, только перечисляя USB-устройства. Второй читает модель и версии. Третий дополнительно проверяет установленные файлы. Последние два требуют ровно одни подключённые очки. Ни один из этих режимов не записывает прошивку.

Автоматические тесты проверяют протокол, несовместимое устройство, частичную передачу, ошибки чтения, восстановление соединения без повторной прошивки и доступность элементов на маленьком окне при разных DPI. Они не заменяют визуальную проверку в очках.
